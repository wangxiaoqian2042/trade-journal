# 仪表盘复刻 · 调研与执行计划

> 目标：把 journalit 的仪表盘拆成可执行的模块，按「数据地基 → 时间维度 → 指标 → 图表/布局 → 联动」的顺序移植进 `trade-journal`。
> 本文只做设计，不含实现。审查通过后再动代码。

## 一、调研结论（以源码为准，不只看截图）

从仓库结构读到的真实规模：

| 层面 | 数量 | 依据 |
|---|---|---|
| 仪表盘目录 | 53 个文件 | `src/components/dashboard/` |
| 指标定义 | **23 个** 可配置指标 | `TopSection/types.ts` → `AVAILABLE_METRICS` |
| 图表组件 | **16 个** 可拖拽 widget | `BottomSection/types.ts` → `AVAILABLE_WIDGETS` |
| 筛选字段 | **16 项** | `dashboardTypes.ts` → `FilterState` |
| 时间档 | **8 个** 预设 + 自定义 | 截图顶部胶囊组 |
| 核心逻辑文件 | `dataUtils.ts` 94KB、`TopSection.tsx` 66KB | 说明计算与渲染都极重 |

一个结论先说清楚：**截图里看到的是"仪表盘"视图，它还有一套"概要"视图**（右上角 概要 / 仪表盘 切换）。这说明它的架构是「一套数据查询 + 两套呈现」，而不是一个页面画到底。我们要复刻的话，必须照这个结构走，否则后面每加一个卡片都要改页面。

## 二、功能分解

### A. 时间维度层

| 元素 | 说明 | 当前状态 |
|---|---|---|
| 今天 / 昨天 / 本周 / 本月 / 本季度 / 今年 / 全部时间 / 自定义 | 8 档预设，胶囊单选 | ❌ 无 |
| 上一周期对比（`+$1,469.52 vs prev`） | 每张指标卡下方一行 delta | ❌ 无 |
| 日期基准（按开仓日 / 按平仓日） | 影响跨日持仓归属 | ❌ 无 |
| 自定义区间 | 两个日期选择器 | ⚠️ 交易列表有，仪表盘没有 |

### B. 筛选层

源码里 `FilterState` 有 16 项：日期区间、账户、账户阶段、标的、策略、标签、错误类型、交易类型（常规/错过/回测）、持仓状态（持仓中/已平）、复盘状态、方向、自定义字段、排除项、匹配模式（AND/OR）、图片标注、图片标签。

我们只做了 5 项（日期 / 标的 / 策略 / 账户 / 方向），且只在交易列表页，仪表盘不共享。

**这是第一个结构性缺口**：它的筛选是全局的，切换后所有卡片一起变；我们的是页面局部的。

### C. 指标层（23 个）

按源码分类：

| 分类 | 指标 |
|---|---|
| performance | 净盈亏、胜率、盈亏比、Sharpe、Calmar、期望值、最大回撤、最佳日、最大单笔盈利、最大单笔亏损、最长连胜、最长连亏、处于回撤的时间、最长回撤 |
| volume | 总交易数、盈利笔数、亏损笔数 |
| average | 均盈、均亏、平均盈亏比(R)、平均风险回报比(基于 R)、平均持仓时间、平均恢复时间 |

每张卡支持：勾选显示 / 上下排序 / 重置默认（`metricLayoutUtils.ts`）。

截图上是 6 张：净盈亏、总交易数、胜率、盈亏比、平均风险回报比、最大回撤。

### D. 图表组件层（16 个）

| 分类 | 组件 | 截图是否可见 |
|---|---|---|
| performance | 累计盈亏（PnL Chart）、多头盈亏、空头盈亏、绩效日历、每日盈亏、交易笔数图、最近交易 | ✅ 累计盈亏、日历、最近交易 |
| breakdowns | 星期表现、小时表现、标的表现、策略表现、标签表现 | ✅ 策略表现 |
| risk | 回撤图、多头回撤、空头回撤、MFE 散点、滚动胜率、滚动统计 | ✅ 回撤图 |

每个组件带 `minSize / defaultSize / maxSize`（网格单位 w×h），配合 react-grid-layout 做拖拽和缩放，布局持久化。

### E. 交互层

- **十字光标 + 跟随 tooltip**（Portal 渲染，避免被容器裁切）
- **点击下钻**：点权益曲线某点 → 交易列表并按该日筛选（`tradeLogDrilldown.ts`）
- **日历**：月视图、每日盈亏 + 笔数、周次角标（W44）、上一月/下一月、点某天筛选
- **策略表现**：右上角切换度量（总盈亏 / 胜率 / 盈亏比 …），横向条形
- **示例日志模式**：截图左下角那个浮层（"此处更改仅用于练习"），用于新手引导的沙盒

## 四、执行计划（分 6 阶段，按依赖排序）

### P0 · 数据地基（必须先做，否则后面全是返工）

1. **统一查询对象**：新增 `DashboardQuery { preset, range, filters }`，所有卡片从同一个 `useDashboardData()` 拿结果。
2. **补字段**：`stop`（已有类型但导入时没填）、`target`、`holdSeconds`（由开平时间算）、`session`（亚/欧/美盘）、`grade`、`mistakes`、`tradeType`（常规/回测/错过）、`status`（持仓/已平）。
3. ~~**补导入止损**~~：**已决定不做**。原计划从止损委托重建初始风险，但止损是独立委托、会撤单重挂，实现成本高且交易笔记不保留委托流水。改为 `stop` 手工填写。
4. **聚合层重构**：把 `analytics.ts` 拆成 `metrics/`（每个指标一个纯函数）+ `aggregate.ts`（按 query 出结果），指标注册表按 id 索引。

> 验收：给定任意 query，能返回 23 个指标值 + 上一周期同口径值。

### P1 · 时间维度 + 环比

5. 8 档预设 + 自定义区间，日期比较统一走本地时区（不吃 UTC 偏移的坑）。
6. 「上一周期」等长回看：本月→上月、本季度→上季度、全部时间→不显示环比。
7. 指标卡右上角 delta：正负色 + 文字（`+$1,469 vs 上月`）。

> 验收：切换 8 档，指标和 delta 全部即时变化，无闪烁。

### P2 · 指标卡系统

8. 指标注册表：`{ id, name, category, format: 'money'|'pct'|'num'|'time', compute(data, prev) }`。
9. 卡片显示/隐藏 + 排序 + 恢复默认，写入 `data.json`。
10. 6 张默认卡对齐截图（净盈亏、交易数、胜率、盈亏比、平均 R、最大回撤）。
11. 支持「涨跌配色」开关（见决策点 1）。

### P3 · 图表组件化 + 布局网格

12. 定义 widget 协议：`{ id, title, size, render(query), actions }`，现有图表全部包一层。
13. 网格容器：12 列，拖拽换位 + 右下角缩放，布局存 `data.json`。
14. 逐个补组件，顺序按使用频率：
    - 第一批（截图同款）：累计盈亏、回撤图、绩效日历、策略表现、最近交易
    - 第二批：每日盈亏、星期表现、小时表现、标的表现
    - 第三批：多头/空头盈亏与回撤、滚动胜率、滚动统计、MFE 散点
15. 响应式：侧边栏 340px 时网格自动塌成单列（这点它做得一般，我们可以更好）。

### P4 · 下钻联动

16. 点图表的点 / 日历的某天 / 策略的某条 → 跳到交易列表并带过滤条件。
17. 交易列表行 → 打开对应 `.md` 复盘（已有能力，接上即可）。

> **落地方式（2026-10-19）**：不另存一套「下钻过滤」，而是把点击翻译成 `Drill` → `applyDrill(query)`，直接改同一个查询对象。
> 好处是点完日历再切回仪表盘，看到的也是同一天的数据，不会两块各算各的。
> - 点日历某天 → `preset=custom`，区间就是那一天（再点别的日子会覆盖，维度条件保留）
> - 点标的/策略/星期条 → 只叠加维度过滤，不动时间档（为此给 `TradeFilters` 加了 `weekdays`）
> - 点多空卡片 → 方向过滤
> - 点累计盈亏/回撤曲线 → 按 `sortTrades` 同序定位到那一笔，直接打开笔记
> - 下钻后自动切到「交易记录」，列表上方给一条 `从图表下钻：X · 命中 N 笔`，可清除条件或返回仪表盘
> - 刻意保留：月历永远显示全量数据（它是导航地图，不是被筛后的视图），否则点一天就被锁死在那天里

### P5 · 高级指标

18. R 倍数家族：`R = pnl / (|entry − stop| × qty × multiplier)`；缺 stop 的笔显示为 `—` 并在卡片角标提示"12 笔缺止损"。
19. Sharpe / Calmar：需要日收益序列，样本 < 20 天时显示"样本不足"，避免给出误导数字。
20. 处于回撤时间 / 平均恢复时间 / 最长回撤。
21. 概要视图（另一套呈现：表格化、无图表，适合快速浏览）。

### 明确不做

- **MFE / MAE 散点**：需要逐笔的最有利/最不利价格，AMP 导出没有，只能用 tick 数据重算，成本远超收益。
- **自定义字段筛选**：我们的 frontmatter 是固定 schema，没有自定义字段体系。
- **多币种**：自用单账户，保持单一货币符号。
- **示例日志沙盒**：对自用无意义。

## 五、难点（按风险排序）

### 附：止损数据的真实现状（用你 9/17 的数据取证）

这是最容易被低估的一个点，先说清楚。同一个合约的两笔交易，原始委托流水长这样：

```
21:55:20  卖出 市价 6手 @29676.46   ← 开仓
21:55:23  买入 止损 6手  止损价 29701.50  ← 保护止损（初始风险 25 点）
21:55:34  取消上一张，改挂 29704     ← 撤单重挂，风险变 27.5 点
22:14:05  止损单成交 @29704         ← 亏损离场

22:49:03  卖出 市价 6手 @29688.75   ← 第二笔开仓
22:49:06  买入 止损 6手  止损价 29708   ← 初始风险 19.25 点
22:49:15  取消，改挂 29741          ← 把止损放宽到 52 点
23:46:52  止损单成交 @29740.71      ← 实际亏损 2.7 倍初始风险
```

由此得出三条硬结论：

1. **止损价挂在独立的委托行上**，开仓行的止损价列是空的。所以必须按「开仓成交 → 之后 N 秒内、反方向、数量匹配的第一张止损委托」去匹配。
2. **止损会被移动**（既有收紧也有放宽）。用"最终成交的那张止损单"算 R 会失真（第二笔会算出 1R 亏损，实际是 -2.7R），必须取**首次挂出的保护止损**作为初始风险。
3. **存在没有止损的仓位**（21 行有止损价 / 50 行总量，且部分已被取消）。这类笔不参与 R 统计，卡片上要标"覆盖率 8/10"而不是悄悄跳过。

顺带发现：这些单子里还有 `止盈` 委托（5 手 vs 持仓 6 手），说明你有部分止盈的习惯，`target` 字段同样可以从止盈委托回填。

| # | 难点 | 风险 | 应对 |
|---|---|---|---|
| 1 | ~~**R 倍数缺数据**~~ | ~~高~~ | **已决定不做**。止损在独立委托行、会撤单重挂，重建初始风险的收益不抵成本；交易笔记里也不保留委托流水。`stop` 字段保留为手工填写，填了才算 R |
| 2 | **涨跌配色冲突** | 高 | 它的截图是绿盈红亏（欧美）；我们当前是红盈绿亏（A 股习惯）。需要你拍板，见决策点 1 |
| 3 | **拖拽布局的实现方式** | 中 | 二选一：引 `react-grid-layout`（现成，+~120KB）或自研 CSS Grid + Pointer 事件（~300 行，零依赖）。见决策点 2 |
| 4 | **「上一周期」的口径** | 中 | 自然周期（本月 vs 上月）还是等长天数（近 30 天 vs 前 30 天）？自然周期更符合直觉，但 2 月会短一截。建议自然周期 + 卡片上标出对比区间 |
| 5 | **手写 SVG 的交互成本** | 中 | 十字光标、跟随 tooltip、缩放全要自己写。我们已经手写了面积图/条形图，加交互约等于重写一遍图表层。是否引 recharts 见决策点 2 |
| 6 | **指标口径一致性** | 中 | 同样叫"盈亏比"，除以毛盈亏还是净盈亏？必须先在注册表里把口径写死并加单测，否则环比会出现"两边算法不同"的假变化 |
| 7 | **重算频率** | 低 | 数据量 71 笔无压力；但布局拖拽时不能触发重算，用 `useMemo` key 绑 query 而非组件状态 |
| 8 | **侧边栏窄屏** | 低 | 网格断点：≥900px 三列、600–900 两列、<600 单列；图表内部再降级（隐藏坐标轴标签） |

## 六、需要你拍板的 3 个决策

1. **配色规则**：跟它一样（绿盈红亏），还是保持我们现在的**红盈绿亏**（A 股/国内期货习惯）？
   我倾向保持红盈绿亏，但要加一个开关，两边都合逻辑。

2. **要不要引图表库**：`recharts` 能省掉十字光标/tooltip/动画的工作量，但打包体积从 274KB 涨到 ~430KB，且它用的是 SVG 不是 canvas。
   我倾向**先不引**，把交互手写在现有 SVG 图层上（我们只需要 5~6 种图表形态，引一个通用库反而更重）。如果 P3 做到第二批发现交互代码量失控，再切。

3. **范围取舍**：P0–P4 是核心（做完就是截图那个水平），P5 里的 Sharpe / Calmar / MFE 你们这类小样本自用账户参考价值有限。
   建议**先做完 P0–P4，P5 只做 R 倍数和回撤统计**，其余先记 backlog。

## 七、建议的落地顺序（一句话版）

> 先把"数据能算出 23 个指标 + 上期对比"这条链路打通（P0–P1），再做"卡片能配置"（P2），然后是"图表能拖"（P3），最后才是"点图表能跳转"（P4）。

顺序不能倒：P3 的拖拽一旦先做，指标和 query 一改，所有 widget 都要返工。
